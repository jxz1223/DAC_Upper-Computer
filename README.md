# 交流/直流传感器波形查看器（一对一 / 一对多）

程序顶部有两组独立选择：左侧选择“交流传感器 / 直流传感器”，右侧选择“一对一 / 一对多”。切换任意模式时都会自动断开串口并切换页面和协议解析器，避免把不同协议的数据混在一起。

一对一页面保持原版界面和协议不变；一对多页面面向 `DC_BLE_Receiver_Muti` 数据中继，最多同时显示8个带独立`NodeId`的传感器（CH1–CH8），适用于交流和直流模式。节点表可滚动，各节点独立颜色、曲线、数据和DAC控制目标。

新增“**四路 ADC**”连接方式，用于一块 STM32WB55 传感器板上的 U4～U7 四路模拟前端。该模式与“一对多”节点中继互不混用：接收器串口默认 `2000000 baud, 8-N-1`，上位机校验 `A5 5A / V1 / 0xA0` 外层帧及其内部 BLE 波形帧，分别显示四路归一化数据和当前仪表放大器增益。旧版一对一交流 16 位协议、直流 DAC 协议及一对多 V2 协议均保持原有行为。

八节点配套固件标识`build=20260909-8N-R1`，中继连接周期100 ms；所有传感器应更新到ACK等待600 ms的配套固件。串口继续使用921600 8N1、V2协议。新版可接收原4节点中继数据，但旧上位机最多显示4个节点，不能用于完整八节点调试。

一对多页面选择设备后，点击“断开并腾出位置”。中继实际断开后会暂缓该设备重连30秒，让其他设备接入；之后有空位时自然重连，无需“允许重新连接”按钮。串口ACK仅表示请求已接受，日志中的实际断开事件才表示位置已释放。该功能需要更新中继固件，旧固件不能识别新增的0x16命令。若在DAC扫描中断开，新传感器固件会恢复扫描前DAC值，扫描不会自动续扫。

满8个显示位置时，新设备可复用离线位置；旧设备历史数据保留在内存，读数仍包含在CSV导出中，重新接入后可恢复显示。CH编号不再保证一直对应同一台设备，请以NodeId区分。所有位置都在线/发现中时不会挤掉已有设备。

继电器与 30 分钟窗口测试：`.build-venv-multi/Scripts/python.exe tests/test_relay_discharge.py`。

精度与 10 分钟窗口测试：`.build-venv-multi/Scripts/python.exe tests/test_lockin_precision.py`。

八节点测试：`.build-venv-multi/Scripts/python.exe tests/test_eight_nodes.py`。也可运行`tests/test_packaged_eight_nodes.py <EXE路径>`验证打包内的应用代码，覆盖八节点、锁相精度、继电器与时长全部测试；此项使用本地Qt依赖，不替代EXE引导程序启动检查，不连接真实串口。中文EXE使用现有`SensorWaveformViewer_New.spec`重新打包，正式启动文件仍为本目录下的同名中文EXE。

## 一对一模式

交流一对一适用于原 STM32WB55 接收器输出的数据协议：

- 串口默认波特率：921600，8-N-1（当前COM16实测）
- 默认时间轴采样率：8000 Hz
- 每帧 246 字节
- 帧头：`8F 8E 8F`
- 数据区：120 个无符号大端 16 位采样值（`uint16_t`，高字节在前）
- 帧尾：`8E 8F 8E`

### 四路 ADC 模式

1. 选择“交流传感器”和“**四路 ADC**”。该模式固定按每路 `2000 S/s` 生成时间轴，波特率会自动切换为 `2000000`。
2. 接收器向 PC 发送的外层帧为 `A5 5A | V1 | Type=0xA0 | Flags | ScanId:u16 | Seq:u16 | Length | Payload | CRC16-CCITT:u16`，其中 CRC 为小端；Payload 为固定 246 字节 BLE 波形帧。
3. BLE 波形帧为 `A6 6A | V2 | 76 | Sequence:u16 BE | SampleRate:u16 BE | FirstScan:u32 BE | 76 x sample24 | Reserved[4] | CRC16-CCITT:u16 BE`。
4. 每个 `sample24` 的 `bit 0..18` 为发射端已归一化的 19 位数据，`bit 19..20` 为通道号 `0..3`（U4～U7），`bit 21..23` 为增益码 `0..7`，对应 `1, 2, 4, 8, 16, 32, 64, 128` 倍。
5. 实时页同时显示 U4/CH1、U5/CH2、U6/CH3、U7/CH4。顶部“统计通道”用于复用原有统计与测量换算区；保存 CSV 会额外包含 `channel`、`amplifier`、`normalized_value`、`gain_code` 和 `gain`。
6. 状态栏显示四路有效帧、BLE 序号缺帧、每路采样率、每通道缓存点数、外层 CRC 错误、内层波形错误和同步丢弃字节数。

## 启动

双击 `启动传感器波形查看器.bat`，或运行：

```powershell
python sensor_waveform_viewer.py
```

BAT 启动器只调用同目录下的最新中文版本 `传感器波形查看器_交流直流合并版.exe`；请勿将 BAT 与该 EXE 分开。工程不再保留英文文件名或历史 EXE 回退版本，避免调试时误启动旧程序。

如果电脑缺少依赖：

```powershell
pip install -r requirements.txt
```

## 操作

1. 选择接收器对应的串口。当前COM16实测波特率为921600；
   也可以点击“自动检测波特率”。采样率默认8000 Hz。
2. 点击“连接”，程序自动识别帧头和帧尾并持续绘图。
3. “显示时长”预设从 1 s 起，包含 10 min、30 min、1 h 和“全部”；仍支持自定义输入。选择分钟档位时，横轴和坐标提示同步使用 min。长窗口仅在绘图时按峰值降采样，原始数据、统计和 CSV 不降采样。
4. 暂停显示后，左键在波形上拖动可选择统计区间；单击波形显示最近采样点坐标。
5. “保存数据”导出 CSV；“保持全部数据”可禁止历史数据随显示窗口滚动删除。
6. 在“传感器测量换算”中输入灵敏度和直流偏置（均可为正数或负数），选择测量类型与输出单位。
7. “显示传感器数据”和“显示去直流波形”可分别控制两条曲线是否显示。

### 直流传感器模式

1. 选择“直流传感器”，默认波特率切换为 115200，也可自动检测。
2. 支持设置 DAC、设置并保存 DAC、起止点扫描、终止扫描和扫描点 CSV 导出。
3. “实时波形”显示 Lock-in 连续读数，“DAC 扫描曲线”显示 DAC—Lock-in 关系。
4. 波形时长支持 ms、s、min、h 和“全部”，保存数据时同时导出 DAC、Lock-in 与 ADC。

## 一对多模式

一对多使用 V2 二进制协议，串口默认并建议固定为 `921600 baud, 8-N-1`。V2 帧带 16 位 `NodeId`，与原直流 V1 和原交流 246 字节裸采样帧均不兼容。

1. 先选择“交流传感器”或“直流传感器”，再选择“一对多”。
2. 连接数据中继串口。中继逐个扫描、连接，先完成 ATT MTU 协商再执行 GATT 发现；节点就绪后会按首次发现顺序固定显示为 CH1～CH4。
3. 每个通道使用固定颜色。默认叠加全部在线节点；取消“叠加全部在线节点”后，只显示节点机架中选中的节点。
4. 交流模式从 V2 `SENSOR_READINGS` 显示 `AdcRaw`；直流模式显示 `Lock-in/Rms`。横轴使用上位机收到数据的相对时间，不使用一对一交流模式的人工采样率。
5. 直流一对多的 DAC 设置、保存、扫描和中止均为定向命令，只发往节点机架中当前选中的在线 `NodeId`，不广播给其他节点。扫描区域会依次显示“等待确认、传感器已接受、正在执行、累计点数、完成/中止”；调试日志同时记录 ACK/NACK 和每批扫描进度。
6. 每个节点有独立实时数据队列和扫描点队列。默认按“显示时长”滚动淘汰历史数据；勾选“保持全部数据”或选择“全部”才保留完整历史。
7. “导出多节点 CSV”会合并各节点数据，并保存 `node_id`、通道、时间戳、序号、DAC、Lock-in、ADC、当前显示字段和值。
8. 状态栏显示 V2 有效帧、在线节点数、各节点队列读数、扫描点、CRC/同步丢弃字节，以及中继上报的 BLE 队列深度、PC 发送空闲槽和重复包计数。

### 继电器放电（PD7，5 秒）

一对多页面的交流、直流模式均有“继电器放电”按钮，仅控制节点机架中选中的在线 NodeId。连接串口并选择在线节点后，点击一次即请求传感器将 PD7 拉高，传感器在 5 秒后自动拉低；断连不会取消传感器的定时结束动作。此功能需要支持新命令的配套接收器和传感器固件，一对一 V1/原交流裸流不支持此按钮。

界面按节点独立显示状态：等待确认、已确认等待状态、PD7 高电平/低电平、状态未知。只有传感器实际上报的状态才表示高/低电平；ACK 不代表完成，界面也不会用本地倒计时冒充完成。高电平或等待反馈时禁止重复点击；离线、重连后状态重置未知。反馈超时只提示状态未知并恢复手动重试，不会自动重发。若传感器仍在放电，返回 BUSY 并上报真实状态，且不会延长这次放电。

控制命令不会因切换选中节点而转向其他传感器。仅清空波形不会清除未完成控制，也不会重置命令编号；新上位机会话使用独立随机编号起点，降低仍在运行的 BLE 会话把新请求当作旧重传的风险。

## 蓝牙调试日志

主界面右上角的“调试日志”按钮会打开独立日志窗口，采集页面不会被替换或清空。日志在窗口隐藏时也会继续记录，最多保留 5000 条。

日志内容包括：

- 串口打开、关闭、自动波特率检测和串口异常；
- 节点首次发现以及 CH1～CH4 通道分配；
- 物理 BLE 建链、ATT MTU 协商、主服务/特征/通知描述符/使能通知各 GATT 阶段、GATT 就绪和连接断开；
- 新版中继断链时上报的 HCI 原因码、断链所在 GATT 阶段和 GATT/中继错误码；
- 带命令名称及原因说明的 ACK/NACK、DAC 扫描实际参数、每批进度、完成点数、恢复 DAC 和协议校验丢弃；
- 传感器或中继通过 V2 `BLE_RAW (0xA0)` 上报的诊断文本。
- 上位机串口写入字节数，以及 `COMMAND_TRACE (0xA3)` 的“中继已收帧、BLE 已写入、传感器事件已返回、ACK/NACK、重试、超时”逐层状态。

日志窗口支持连接/协议/设备/错误分类筛选、暂停刷新、自动滚动、复制可见内容、CSV 保存和清空。节点文字颜色与多节点波形通道颜色一致。

一对多 V2 的 `LINK_STATUS (0xA1)` 是真实中继链路事件。新版载荷为 `State, LinkCount, PeerAddress[6], HciReason, GattStage, Detail, AttMtu:u16`，GATT 就绪日志会显示实际 ATT MTU；查看器也兼容旧版 8/11 字节载荷。一对一旧协议没有链路状态帧，因此日志只会在收到首个合法数据帧时显示“推断蓝牙数据链路可用”，不会把它标记成真实 HCI/GATT 事件。

`COMMAND_TRACE (0xA3)` 的载荷为 `Stage, CommandType, Status, Attempt, BleTxDepth, FrameLength, ObservedType, WriteHandle:u16`。点击 DAC 扫描后，上位机自己的“已向系统串口发送缓冲区写入”只表示 Windows 接受了待发送字节，不表示中继已经收到。第一条设备侧证据应是“中继 UART 已收到并校验完整命令帧”，随后是“已加入 BLE 队列”和“BLE 写入接口已接受”。若日志停在上位机发送缓冲区写入，问题位于 UART 电气连接、波特率或中继接收/解析；出现 UART 校验成功但没有入队，则检查 NodeId/链路状态；出现“BLE 已写入”但没有传感器 ACK/NACK 或 `SENSOR_RX_COMMAND`，则检查目标传感器固件、RX特征和无线链路。为了保证实时性，传感器ACK/NACK现在优先于 `SENSOR_RX_COMMAND/SENSOR_FRAME_VALID` 调试文本发送，因此日志中ACK先出现属于正常现象。

中继使用256字节循环UART RX DMA接收921600 baud命令。短暂的UART空闲只用于报告当前DMA写入位置，DMA本身保持运行，允许USB转串口分包继续拼成同一协议帧；只有连续250 ms没有新字节时才清除半帧并尽可能返回“帧长度错误”。下一条命令从新的帧头重新同步，不会再出现“第一次无响应、第二次借用残帧后CRC失败”。

### V2 串口帧摘要

帧格式为：

```text
A5 5A | Version | Type | Flags | NodeId:u16 | ScanId:u16 | Seq:u16 |
PayloadLen | Payload | CRC16-CCITT:u16
```

- `Version` 固定为 `2`。
- 多字节整数为小端。
- CRC 初值 `0xFFFF`、多项式 `0x1021`，覆盖 `Version` 到 `Payload`。
- PC 下发业务命令必须填写具体传感器 `NodeId`；界面不会发送广播 DAC/扫描命令。
- 详细中继调度、扫描连接、重传和流控策略见上级目录的 `MULTI_NODE_ARCHITECTURE.md`。

- `RELAY_DISCHARGE (0x17)` 为定向继电器命令，载荷为空，固定放电 5 秒；ACK/NACK 沿用命令的 `ScanId/Seq`，确认载荷为 `[0x17, status]`。
- `RELAY_STATE (0x94)` 的载荷恰好 1 字节：`0` 为 PD7 低电平、`1` 为高电平；`ScanId` 来自实际接受的放电请求（上电可为 0），`Seq` 为传感器传输序号。长度/值不符的状态帧会被丢弃并记录日志。
- V2 实时读数 (0x93) 与扫描点 (0x91) 的 `Flags & 0x08` 表示锁相幅值使用 `uint32 × 0.01`。实时每点为 `seq:u16, dac:u16, lockin_centi:u32, adc:u16` (10 字节)，扫描每点为 `index:u8, dac:u16, lockin_centi:u32` (7 字节)；载荷首字节仍为点数。
- 无该标志的旧 V2 和一对一直流 V1 继续按原整数幅值解析。点数与载荷长度不一致时丢弃整批数据并记录日志，避免错误缩放或错位。
- 更新顺序：先使用本次重新打包的上位机，再烧录配套高精度传感器固件；旧上位机不支持新载荷布局，不应连接已升级传感器。
- 锁相幅值、统计、光标和 CSV 固定显示两位小数；DAC、ADC 仍保持原整数语义。升级传感器配套固件才能获得 0.01 分辨率，旧固件整数数据仅显示为 `xx.00`；小数位数不代表硬件绝对准确度。

波形纵轴、鼠标坐标、最小值、最大值、峰峰值和CSV的采样值列也均为十进制；
串口中的十六进制字节只在程序内部用于组帧，不向用户展示。

测量类型和单位支持：电场（V/m、kV/m、kV/mm、kV/cm）、磁场（GS、T）、
电压（V、kV）和电流（A、kA）。所选单位同时作为灵敏度、直流偏置和换算结果的单位，
切换单位不会自动改变已输入数值。换算公式为：

- 传感器测量峰峰值 = 灵敏度 × 原始峰峰值 + 直流偏置
- 传感器测量有效值 = 灵敏度 × 去直流后有效值 + 直流偏置

采样率只用于生成时间轴，不改变传感器实际采样速度。

状态栏分别显示有效帧、非零帧和全零帧。如果持续提示“数据区为全0”，
说明查看器已经收到合法数据帧，但传感器发出的120个采样值本身均为0，
应检查传感器 ADC 输出、时钟/片选接线及采样程序。
